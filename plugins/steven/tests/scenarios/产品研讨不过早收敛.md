# 产品研讨不过早收敛回归场景

## 输入

1. 用户：我想做一个帮我安排今天三件事的小工具，但还没想清楚具体怎么做。
2. 用户纠正：我每天会发生什么事不能预知，已知事情只占一半，未知事情也必须照顾到。
3. 用户补充限制：我不想要复杂的计划系统，只想要非常轻薄极简的小工具。

## 通过行为

- 自动进入产品研讨，并清楚知道当前仍在探索。
- 把每次新信息用于理解真实情境、现有应对、失败后果或关键矛盾；允许推翻上一轮理解。
- 用自然问题、反例、质疑或可推翻的暂定假设继续共同研讨。
- 只有语义证据足以进入客观调研时，才综合形成阶段性全貌和推荐。

## 失败行为

- 首轮就给出推荐产品方向和 A/B/C 方案菜单。
- 用户每补充一条事实，就立刻改造并推荐另一套功能方案。
- 在真实场景和关键假设仍不清楚时，声称“只剩一个关键决定”并催促用户选择。
- 只口头声明“研讨中”，实际仍以交付方案为每轮目标。
