# 需求池与授权状态

LLM 判断需求、P/D、关系与批准语义；工具只精确读取、比较、写入和回读。先读取项目绑定的仓库、Projects、字段与选项，不猜标识。只用项目定义的中文状态/当前流程/P/D/所属项目；平台内置 Status 不作业务状态。

## 来源与承接

- 来源正文只存一次。一个来源可有多个独立项目承接，各有稳定身份、P/D、业务状态、流程、PRD/迭代和验收；共同实现则标唯一交付方及依赖。
- 只记录：先查重并说明复用/关联，保存原话与来源、简短整理和独立判断，保持待处理、无流程，不创建 PRD、不启动研讨。候选项目可零、一或多。
- P 是紧急程度，D 是重要程度；用户给出则沿用，未给按下表语义判断并说明，不因刚提出或核心重要就判紧急。来源初始 P/D 与各项目承接 P/D 分开：缺失的来源等级也须补判，不能因项目分别分级而留空；已有有效等级保持其来源，不用汇总等级覆盖项目差异。
- 提取进入项目时，推荐复用、合并、拆分或暂缓；用户批准方向与活动范围后再正式承接。合并/拆分保留关系链和有效末端，不发明业务状态或仅按源卡号去重。

| 等级 | P：紧急程度 | D：重要程度 |
| --- | --- | --- |
| 0 | 立即处理：严重损失或硬截止 | 核心：缺少则产品或核心闭环不成立 |
| 1 | 本轮必须：当前任务、阶段或版本关键路径 | 重要：明显影响主要用户、业务或关键能力 |
| 2 | 正常排期：有时间价值，暂不影响主线 | 一般：有明确改善，不影响核心闭环 |
| 3 | 暂无时限：可长期等待 | 可选：探索、细节或价值未证 |

## 需求附件

只保存确实帮助理解、复现或验收的图片，并保留所属需求、来源、日期、用途和读取条件。能安全取得原图时保留原字节；只有宿主处理图或预览就注明，不重画后冒称原图。相同内容复用同一受控资产及多个引用；相似图片不直接合并，跨项目去重不能扩大访问范围。

敏感内容与证据无关且可可靠去除时，只持久保存注明处理的脱敏图；用户原文件不擅删。敏感部分就是关键证据、或脱敏影响无法判断时，先带保存范围与风险请用户决定，不自动留存或外传。密钥等不得入Git；误存时停止传播，说明历史/远端仍可能保留，申请实际清除与必要凭据处置，不以删链接冒称清除。

优先已有获准的私有存储，核实平台限制及实际容量；大批量/过大资产不盲塞仓库，不擅自新增图床、LFS、付费或公开范围。保存、需求绑定、原字节回读分别确认，入口应能定位正确版本而非只留临时路径。上传结果未知先查原对象，绑定失败补原引用；失效/损坏先合法恢复，缺少决定性图片才请求重传，不凭文字猜图。关闭需求不自动删仍有价值或共享引用的图；迁移核对身份/引用和无原聊天恢复，退出本次临时副本。

## 底稿和投影

authorized.json 是批准与动态事实的唯一写入端，不存来源正文；project.json 是轻量导航，GitHub 中文字段是投影。没有 PRD 的新项目可以合法存在，现行/在编指针为 null，不能造空 PRD 通过检查。

候选 schema 3 按 iterations（迭代）关联 prds（唯一 PRD 记录），projectDemands 关联迭代；批准范围从实际批准对象取得，绝不从恰好已有的承接数组反推。核对批准集合的有效末端身份与实际活动集合完全相等，缺项、多项、空集、错项目、旧迭代串入均要识别。未来多个迭代可研讨，正式研发最多一条；具体门槛见 [生命周期](delivery-lifecycle.md)。

旧格式只读兼容，未知字段保留并提示。迁移需确认旧证据、隔离验证和适配安装的受控切换；不得凭补字段创造批准。

## 写入完成

按 [受控操作](alignment-and-recovery.md) 记录依据、写前基线、完整目标和回执，沿同一操作补齐。记录需求须完成来源卡与项目项回读、底稿校验、可信 Git 远端回读和必要投影；单边成功只报“部分写入、对齐阻塞”，不重复建卡。

没有绑定/权限、只读限制或尚未写入时，直说“尚未持久保存到需求池”；不能把对话复述称为收录成功。校验器证明结构及确定性差异，不证明需求正确、授权真实或远端已回读。

向用户合并一次简明结果：新增/复用、P/D 理由、项目关系、实际状态与链接；编号和载荷留在证据中。
