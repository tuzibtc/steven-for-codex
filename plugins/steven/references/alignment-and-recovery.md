# 受控操作、对齐与恢复

LLM 决定目标、批准含义和影响；工具只处理确定性读写。普通文件编辑不强制开启整套恢复流程；受控状态/定稿/跨端同步必须保留同一操作的可恢复证据。

## 一次操作

读取权威基线 → 计算完整目标与影响 → 取得适用授权 → 排他写入 → 各端独立回读 → 更新真实停点。内部保留操作身份、依据、对象、基线摘要、目标、回执和未完成项，不累积另一套运行数据库。

- 已有底稿的本地受控写入复用插件的 [状态模块](../scripts/lib/state.mjs) 读取/校验与 [写入模块](../scripts/lib/controlled-write.mjs) 的 commitState；按其真实接口提供项目根、操作身份、候选状态及读取所得修订/两个摘要，不重造锁或写入器。旧格式迁移候选由同模块 migrateLegacy 在明确映射与迁移批准下产生，不自动安装或切换真实项目。
- 本地写入在锁内重读 revision 与摘要，拒绝陈旧结果；锁属于创建者，不能按年龄自动抢锁。并发后写者重新读并计算，不让旧子任务覆盖新事实。返回的 committed 只说明权威文件是否已写，ok 只说明本地回读；任一都不代替外部成功或用户批准。
- authorized.json 单文件原子替换，然后生成 project.json/外部投影；这不是跨文件/网络事务。投影失败保留权威事实与差异，标记部分完成并阻断依赖它的推进，不能只改投影就宣称底稿已对齐。
- 读取失败、状态不明、暂停失败均保留未知；先查询原操作/原回执/原对象，不为“验证阻断”再次执行可能有副作用的动作。只有确定未发生且原授权仍有效才继续必要写入。
- 写入器自动把旧未解决操作保留在 `lastOperation.unresolved`，普通更新或 `previousOperationId` 不代表已解决。Agent 核实原对象后，在新操作的 `resolvedOperationReferences` 按原操作身份提供真实核查依据引用；脚本只检查结构，不代替核实。已解决项退出活动记录，历史证据由 Git/既有证据保留。
- 旧待办缺少影响范围时，先按原对象、环境和证据核清迭代。用 `lastOperation.operationScopeAssignments` 按原操作编号提交 `affectedIterationIds` 和 `evidenceReference`。写入器仅补上缺失的范围和依据，原状态、回执与后续待办继续保留。已登记范围不可用此入口改写。写后分别检查相关迭代仍受原待办约束、无关迭代可按自身状态继续。
- 每个必要检查均核对退出、正文和回读。后项成功不覆盖前项失败/告警/未执行；只停止受影响链，恢复后接回主任务。
- 本地路径检查真实边界（含符号链接），不覆盖用户无关改动；失败收尾只清理本次拥有的临时物和锁。

## 原子定稿

候选内容、完整差异先用人话披露；后台锁定精确文件、项目既定可信私有远端、分支、活动承接集合、PRD 指针与必要投影。缺绑定/权限/底稿/远端回读条件时只能审核内容，不能请求会被理解为立即生效的批准。不能借定稿暗建远端或在本地冒充成功。

一次完整无保留语义批准覆盖该对象的正式提交、推送、远端回读和必要投影；局部审核/带保留批准不触发。逐项确认 Git、远端 PRD、底稿、全部必要需求/状态/流程投影；任一缺证，保持未生效，不进开发或技术方案。格式、引用、传输与对账恢复可沿原批准；产品事实改变使原批准失效。没有一般化自举例外。

## 恢复与退出

对人工漂移、部分写入、中断、并发、新克隆、版本/路径变动均证明发现→阻断→恢复→全量回读。按每类事实权威源解决，不用最后写入者覆盖，也不以中文关键词猜业务许可。

必要文件进入可信 Git 历史及工作区外可恢复副本；lastVerified.gitCommit 只表示写前已读基线，不追逐包含自身的 HEAD。写后提交/远端现场回读，禁止为自引用无限追加提交。

GitHub 独有原文、评论、关系、标识与覆盖边界进入最小只读恢复包；隔离恢复、检查身份/版本并和当前源对账，未对齐不推进。包不是第二编辑源，不含凭据。替代旧路径同时核查本次安装的外部配置/挂钩/缓存及新会话加载；不扫描或删除无关项目。清理前核准精确目标与可恢复证据，暂留物有用途、退出条件和最晚节点。
