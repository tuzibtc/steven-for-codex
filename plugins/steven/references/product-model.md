# 产品模型与表达

本文件帮助 Codex建立完整产品模型；具体产品判断仍由 LLM/Agents 基于当前 PRD 完成。

## 顺序

1. 核心业务流程钉住从真实触发到主要用户结果成立的唯一价值骨干。
2. 功能架构补齐所有职责、事实归属、接口、依赖和失败隔离。
3. 内部任务状态模型穷举合法入口、事件、前置条件、状态、结果、异常、恢复、版本和分支。
4. 用户原型只投影用户完成任务必须看到、操作或决定的部分。
5. 两层一致性通过后，才可向用户展示低保真原型。

## 每层必须交付的产品判断

### 一张核心业务流程

- 以整个项目为对象，从真实触发到主要用户结果成立；只保留缺少后产品不能成立的价值骨干。
- 关键业务判断若直接决定主要结果，必须留在主图；生命周期、内部写入、普通异常和恢复控制下沉，不让用户审核图组。
- 图前先用文字验证触发、参与者、价值交接、关键判断和最终结果；图只是表达，不是事实来源。

### 功能架构

必须覆盖全部当前有效需求和必要补齐项。每个一级职责写清：产品价值、拥有的事实或状态、提供与需要的接口、依赖方向、失败隔离、来源需求和验收。不能按页面、文件夹、Skill 数量或现有代码随手分组，也不能把需求清单换个分类冒充完整产品。

### 内部任务状态模型

每个真实用户任务至少定义：身份、合法入口、事件、前置条件、状态、迁移、成功/失败/取消/等待结果、普通异常、安全去向、恢复、版本与分支。模型必须能被确定性检查器或项目测试自动验证；自动检查只证明结构，Codex 还必须语义审查状态是否代表正确业务事实。

### 用户产品原型

只从已验证模型投影。保留用户为完成任务必须看到、操作、理解或决定的部分；隐藏机器能根据批准事实自行完成的锁定、字段维护、对账、补偿和普通恢复。用户原型的每条路径必须能反查内部模型事件，任何原型独有路径或模型未投影的必要体验都属于不一致。

## 内部任务状态模型最低检查

- 全部状态可达；不存在孤立状态。
- 每次转移都有合法事件与前置条件；受保护关口不可绕过。
- 成功、失败、取消、等待和恢复终态语义正确。
- 异常有安全去向，恢复可重入且不产生重复事实。
- 首次研发、定稿后变更、已完成版本迭代不串线。
- 通用交互可以复用，但业务语义不同的状态不能为减少页面或代码而合并。

## 用户原型投影门

- 主路径、关键决定、结果反馈及影响用户结果的失败与恢复可以实际走通。
- 机器能依据已批准事实可靠判断、执行或恢复的内部工作，不变成用户按钮、表单或审批。
- 原型不得反向定义业务合法性；发现错位应修内部模型或 PRD。
- 无独立页面的脚本、自动化和第三方宿主扩展用行为演示或真实宿主走查，不强造网页。

## 交付前门禁

1. 当前版本全部有效需求都有归属，预先植入的冲突、依赖、权限、异常、恢复和非核心业务缺口都有结论。
2. 核心业务流程、功能架构、内部模型、用户原型和 PRD 使用同一事实；发现差异回到最早拥有该事实的位置修正。
3. 自动验证报告列出总状态、可达性、非法迁移、关口绕过、终态、恢复重入、版本串线和孤立分支；不能只写“已验证”。
4. 用真实任务走通主路径和影响用户结果的失败/恢复；无界面项目用真实输入输出和宿主行为代替页面。
5. 内部门全绿后才向用户展示一张核心流程和必要原型内容；功能架构审核只谈产品职责，不让用户审代码结构。

## 九类产品职责

| 责任 | 结果 |
|---|---|
| 公共规则与安全 | 规则优先级、身份、权限、错误和审计边界一致 |
| 交互装配 | 正确理解复合自然语言、当前上下文和用户决定 |
| 产品判断 | 问题、反证、推荐、取舍和可推翻条件清楚 |
| 事实中心 | 需求、PRD、关系、版本和追溯各有唯一归属 |
| 工作控制 | 选择正确入口、阶段、状态模型、影响范围和下一工作包 |
| 产品表达 | 流程、架构、原型、视觉和图表准确且可理解 |
| 研发交付 | 实现、测试、集成、清理、版本和环境结果真实 |
| 对齐与验收 | 写前基线、授权、写后回读、阻断、恢复与验收结论可信 |
| 外部适配 | 以最小权限使用 GitHub、浏览器、设计和部署能力，不替产品做决定 |

这些是职责边界，不要求建立九个常驻 Agent、九个服务或九套目录。Codex 可按任务动态使用一个或多个 Agents/Skills，并自行决定并行方式。

委派仍服从当前宿主权限；不可用时主 Agent 自行完成，不新建一套调度系统。流程图、技术与视觉标准首先服务 Agent 的快速正确执行，用户审图只是必要产品决定，不代替内部完整性检查。

专业标准沿项目生命周期维护，标清适用 PRD/版本、与旧版的保持项及变化理由；PRD 绑定其身份与范围，冲突时回到产品事实裁决。能由现有标准/可执行契约表达的事实不复制成新文件，后继 PRD 引用有效标准而非全文累加。

## 表达质量

- 复杂关系明显适合图时才画图；精确对照优先用表。
- 正式图必须自然中文、层级清楚、可完整预览、可缩放、单一可编辑源和同步派生结果。
- 核心骨干始终一张，其他复杂细图可总览加按需展开；交付前在实际阅读环境检查逻辑、文字连线、裁切与缩放，提供完整预览和 SVG，图源改动同步导出并清理失效派生物，不把作图质量交给用户验。
- 参考基线固定任务和质量，不固定版式、颜色或节点位置。
- 真实界面的统一质量门同时检查可用/合规/无障碍/无故障，以及项目气质、审美、工艺和完成度；任一部分失败都不交付。
