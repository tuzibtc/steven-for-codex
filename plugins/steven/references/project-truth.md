# 项目事实与唯一来源

先认清本次对象与任务，再读取必要事实；聊天印象、标题、缓存和旧报告不能代替来源。

| 事实 | 权威来源 |
| --- | --- |
| 产品目标、范围、保持项、验收 | 对应任务/软件版本的已生效 PRD；专业标准从属于它 |
| 稳定协作约定和事实入口 | 作用域内 AGENTS.md（项目工作规则） |
| 需求原文、补充、评论、附件 | 已绑定 GitHub 来源卡；正文不复制成第二编辑源 |
| 批准、承接关系、动态状态、迭代许可 | 最近合法决定对应的 authorized.json（授权底稿）；GitHub 字段和 project.json 是投影 |
| 代码与安装、发布结果 | 实际文件/Git、加载路径与平台回读，分别核实 |
| 历史背景、经验 | 关联原证据；记忆只作查找线索，不能批准动作 |

## 读取与持续履职

- 研讨某需求前完整阅读相关卡正文、补充与评论，并核对影响判断的附件和最新决定。分页/截断先补读；无法获取则说明缺口，继续可行查证，不假装已读。接管或整体范围审查核对关联全卡，局部任务仅相关卡和依赖。
- 已完整读取且确认未变化可复用。新上下文从轻量入口恢复：目标、对应 PRD/标准、当前授权、已完成证据、未完成工作和下一步；不默认加载全部历史，不凭“已完成”摘要跳过必要证据。
- 源卡与 PRD 冲突时追查决定的对象、时间和生效条件；保护正在使用的现状并查明差异，不让代码反向取代 PRD。详见 [PRD 宪法](prd-constitution.md)。
- 底稿初始化前按项目已核对中文字段建立基线；初始化及回读后只从底稿投影，不能同时双向写回。不把结构校验当作批准语义核实。

## AGENTS 与经验

在项目管理授权内，Agent 自主维护项目级 AGENTS.md，包括自己写的规则：整理、去重、替换过期入口、继承质量优先的精益原则；不逐句找用户批准。只放稳定约定和事实入口，不复制 PRD、技能全文或动态进度；不改变已批准含义，不覆盖用户无关规则，不扩大全局作用域。产品事实变化仍走后继 PRD，宿主权限仍有效。写后查引用、矛盾、旧规则残留和实际加载。

用户触发问题或获准任务发现问题时，先检索相关项目经验并验证适用版本、环境与症状；不要自动巡检。修复后优先把可复用事实留在现有技术/设计标准、回归测试及短索引：症状与触发、原证据、已证根因/未证假设、失败尝试、已验证解法、适用条件和验证方法。不新建经验数据库，不堆聊天流水。经验失效则纠正、合并或退出；不能覆盖当前 PRD，也不能无条件照搬旧修法。
