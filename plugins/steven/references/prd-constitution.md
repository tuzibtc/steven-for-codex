# PRD 宪法与变更

当前任务对应的已定稿且生效 PRD 是产品事实与验收的最高标准。流程图、技术/设计标准、代码、测试、状态和经验均从属于它；用户新决定发起变更，不直接覆盖旧定稿。宿主权限与安全规则不因产品文档而降低。

## 内容与冲突

- PRD 优先服务 Agent 准确执行完整产品。保存规则、理由、边界、保持项、来源和验收依据；不保存聊天流水、动态日报、临时操作日志。必要原始证据用可回读引用保留，不能删掉独立判断所需的上下文。
- 专业标准承接实现细节，PRD 绑定其身份、适用版本、约束和冲突处理；后继 PRD 引用仍有效部分，不逐版复制全文，也不产生另一份执行版真相。
- 已用功能在 PRD 漏记时，先保护现状并查原卡、批准和版本，分清实现偏离、PRD 漏承接、尚未决定。不能因代码存在直接合法化，也不能因漏记直接删除。确需修订产品事实则带证据、影响和推荐请求批准后继 PRD；同时修正造成遗漏的承接/审查方法。
- Bug、技术纠正、回归和不改变产品事实的视觉落实在现行依据内修复；改变功能、流程、权限、数据、约束或验收才走后继 PRD。

## 不可变与生效

定稿正文、身份及文件名不原地修改。后继版本独立形成并核对冲突、依赖、附件与验收影响；旧定稿作为历史或仍适用旧版依据，不作为并行“最新版”。

纯路径迁移仅在项目 PRD 明确允许的类别及授权范围内进行：身份、文件名、字节、摘要不变，不覆盖目标，不越界，引用和派生入口同步回读，旧路径按批准条件退出；否则先确认。

碎片/草稿不能开发；内容获批不等于已生效。[原子定稿](alignment-and-recovery.md) 的完整 Git、远端、底稿和必要投影回读通过后才放行。用户当前新指令与定稿冲突时只停受影响工作，说明差异、后果与推荐，不能暗改或自行选择一方。
