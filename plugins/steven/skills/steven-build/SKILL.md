# 研发实施

以任务对应的生效 PRD、适用流程/技术/设计标准和本轮授权为边界。读取相关事实、代码、用户已有改动及验证环境；目标和阶段明确就直接接续，不重新接管、研讨或恢复全项目历史。事实入口不清或涉及规则/经验维护时读取 [项目事实](../../references/project-truth.md)，依据齐备的局部修复不额外加载通用参考。

## 增量执行

先确认故障或可观察的新结果，找到原对象、主链、接口、数据和必须保持项。沿受影响能力检查必要输入由谁产生、保存、传递和消费，结果如何回到原链路；迁移或清理不能删掉下次仍需的事实。同名功能存在不证明连接仍成立。新能力接原框架/流程分支，不重建平行模块；仅改视觉时功能、流程、权限和数据不动。发现 PRD 漏项先保护现状查依据，不擅自增删。

从现有经验找相关症状并验证适用性；用复现、日志、原卡证据和反例检验根因，不能只凭历史归因。选择在质量与安全成立后总成本最优的修法，而非机械最少改行数；必要清理与回归一并完成。

当局部产出增加而整体仍不可用，判断下一工作能减少哪项关键约束，或是否为不可替代的前置；不能用处理数量代替结果，也不因慢就停止必要研究。反复受阻或耗时偏离预期时，利用现成轨迹区分实现/验证、平台等待、重复取材、返工与方向偏离，针对首个失效调整方法；没有数据不猜比例，不加固定时限或重复实验。获准的等价方法调整自行做，路线被推翻或重要新增投入带具体推荐交用户。

已授权范围包含实现、运行、检查实际结果、修复本次问题与约定交付。中途汇报后继续，不在只定位/改完/跑一次测试时结束等“继续”。内部步骤不重复申请，产品变化或新外部影响走 [授权](../../references/protected-actions.md)；研讨期独立修复须明确批准。

## 把实现接到真实结果

从交付要求和受影响保持项逐项对应验证，不凭“几个测试全绿”推断完整。主链与关键边界要能辨对错：权限的允许/拒绝、关系的本人/他人、写入的成功/失败/重开等按实际合同选择。重要反例进入可重跑测试；新资源核对加载，数据渲染保持原安全边界。需要 UI 的结果必须实际操作及查看，命令测试不能顶替。

测试随工作块保存到现有入口，别只留内联命令；不写死临时服务地址，测试数据可恢复，临时物遵守任务目录限制。独立检查可批量但逐项辨认退出与结果；遇权限拒绝重新核对动作/目标，不换工具绕过。充分且未变的证据不重复跑；停滞才沿原对象恢复。

## 收尾仍是任务的一部分

交回前按已有标准逐项核销约定结果、保持项、回归、清理和真实停点；简单任务不另建文档。每句“已完成/验证通过”须找得到对应实际动作与结果，没做过不能从相似检查或代码推断；发现漏项继续执行。更新已有任务入口，不提前标绿。清理替代实现和自己的临时物，保留必要失败证据及无关修改；未知外部结果留原回执，不重发。

有可行获准工作就继续。某个验证、外部动作或发布受限时，只阻断依赖它的部分；先检查原授权内达到同一结果的替代方法，继续独立可做的实现、隔离验证和交付准备，不把拒绝一种方法扩大为放弃目标，也不为保持运行制造无收益工作。只有约定结果完成、暂停，或剩余有效路径确实均需用户决定／外部变化时交回，明确证据和未完项。规则/插件修改分别验证源码、安装、实际加载及行为，不混称；局部验证不替代用户正式验收。整版交付或完成边界不清时，按 [完成口径](../../references/evidence-and-completion.md) 接审查、适用设计审查和验收；局部修复按上述保持项与实际结果收尾，不重启整套流程。
