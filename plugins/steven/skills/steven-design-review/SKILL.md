# 设计审查

审查已实现体验，不重新发明方向。读取现行 PRD、流程、适用技术/设计标准及 [浏览器安全](../../references/browser-safety.md)，沿用项目环境；无独立界面按范围如实不适用。

先对照设计前实现与本次差异核对原功能/流程/数据，非视觉行为变化须有获批依据，不能把自发功能优化当设计细化；再查看实际界面与真实服务的完成效果。桌面/窄屏、关键页面/分支、加载/空/失败/禁用/成功状态、刷新/重开和异常恢复按风险覆盖，不能只看首页。

实际操作并查看截图，确认布局/层级、字色间距、组件/图标、反馈/动效和内容；检查键盘、焦点、语义、对比度、触控/缩放、适用兼容性/性能和控制台。新资源存在不等于已加载，截图生成不等于已审阅。自动检查只是辅助，审美工艺、产品适配和可用性不合格仍须改。

项目可控网页以 [WCAG 2.2 A/AA](https://www.w3.org/TR/WCAG22/) 为底线，纳入项目设计标准并覆盖适用关键状态：自动确认违规为零，工具不能判断的项人工核查，不擅自排除规则。核验普通文字4.5:1、大文字及必要控件/状态图形3:1对比度，完整键盘任务/清楚焦点，文字放大200%不丢信息或功能，320 CSS像素宽无需双向滚动，操作目标至少24×24 CSS像素或满足标准例外。区分真实浏览器缩放和字号模拟；自动绿灯不等于全部合规。其它平台沿已确定的正式标准，无独立界面不强造网页。

发现项区分业务回归、标准不符、未实现、环境受限和审美建议，给位置、影响、依据与证据。含糊反馈先带具体诊断选项确认，未经明确批准不推翻已选风格。

获准交付中的缺陷回研发/视觉修复，再检查受影响原业务及设计；只读审查则报告不擅改。保留各项独立结果和必要画面，不能后项成功掩盖失败。按 [完成口径](../../references/evidence-and-completion.md) 返回原任务，不把局部设计通过说成整版验收。
