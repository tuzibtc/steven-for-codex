# 产品验收

以任务对应的生效 PRD 为最高标准，同时对照适用流程图、技术与设计标准。按 [证据与完成](../../references/evidence-and-completion.md) 判断；局部验证不重启全产品验收，普通项目也不强加史蒂文本体实验。

## 真实结果与 Bug 清理

锁定同一候选版本、环境、批准范围和保持项，逐项建立要求/场景/前置/操作/预期/实际/证据/结论。既从要求找实现，也从现有功能找漏项与越界；覆盖正常、异常、权限、状态、跨环节交接、持久化、恢复及受影响旧能力。重要缺陷用反例证明测试能抓住，正常样例防误报。

运行实际入口与服务完成用户全链目标。代码/配置存在、测试全绿、各段单独通过都不能替代端到端成功；UI 使用真实浏览器和图片查看，平台结果查同对象回执。环境阻塞、未知、跳过、证据不足分别列明，不判通过。

验收失败主动回到问题所在技术开发或视觉设计，按既定标准修复/补齐并做受影响回归，再验同一最终候选；不是仅重验，也不降低标准。只读验收委托则报告修复方向，未获修改授权不得改。清理已知 Bug、断链和遗漏，确认测试可重跑、证据可回读、版本/任务入口一致及临时资源退出；不承诺绝无未知 Bug。

## 正式交付

内部通过后简明展示真实结果、风险与体验方式，按项目要求请求正式用户验收；确认前保持待用户验收，不记“已实现/已完成”。部署独立，不能因未部署阻断后继合规开发。

对外发布测试放在内部必要验证之后，另取具体授权，可按用户批准多次/不限次但不扩范围。失败/未知先查原对象，不自动重发。用户仅承担最终使用判断，不承担逐项找内部遗漏的责任。

## 能力型产品

仅当被验收产品 PRD 要求时，核对隔离/陌生项目、继承能力、正反例、新会话与新克隆、原生对照、源码/安装/加载/真实行为。按现行条款和批准的成本边界选择取证，不把历史实验套件当每次增量的必跑流程。优先复用适用证据和正常工作；额外验证的价值、历史证据适用性及比较口径按 [证据与完成](../../references/evidence-and-completion.md)，不以规则文字或模拟替代真实能力。

史蒂文的研讨能力须在真实多轮纠正与新事实中体现：主动推理、反证和有效引导；既不能“复述＋问卷”，也不能一纠正就膨胀成更大方案。验收矩阵从当前 PRD 重建，不复用旧报告的通过标签。
